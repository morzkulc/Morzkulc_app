## 2. System jobów (`service_jobs`)

### N1 — retry z backoffem nie działa
| | |
|---|---|
| Fakt | `jobProcessor.ts:88` po błędzie: `status = "queued"`, `:108` `nextRunAt = now + backoff[attempts]`. Ten zapis odpala `onServiceJobCreated` (`onJobCreatedWorker.ts:4`, `onDocumentWritten`) natychmiast; claim odrzuca w `jobProcessor.ts:36` (`nextRunAt > now`). Nic nie odpala joba ponownie po upływie backoffu. |
| Skutek | Każdy błąd taska (chwilowy 5xx Google API, brak tokenu, limit Sheets) = czekanie do `serviceFallbackDaily` 03:30 (`fallbackDailyWorker.ts:44-50`). Maks. 1 próba/dobę → `maxAttempts` = 5 dni do `dead`. Backoff `[30,60,120,300,900]` z `service_config.ts` to martwa konfiguracja. Dotyczy: mail powitalny, grupy Workspace, wpis do arkusza, wszystkie powiadomienia. |
| Uwaga | Raport 09.09 (§ system jobów) opisuje retry/backoff jako działające — niezgodne z kodem. Testy na `fake_firestore.ts` nie modelują triggera, więc nie mogły tego wykryć. |
| Fix | Scheduler `onSchedule("every 10 minutes")` z tym samym kodem co fallback (`queued && nextRunAt <= now`). Alternatywa: Cloud Tasks z `scheduleTime`. |
