# 02.11 — Zapisy i opłaty za imprezy klubowe — PLAN

## Stan obecny (fakty z kodu)
| Element | Jest | Brak |
|---|---|---|
| Impreza | `events` (app/arkusz imprez, zatwierdza zarząd, `kierownicy[]`/`kierownikUids`) | zapisy, ceny, płatności |
| Uczestnicy | tylko „Interesuje mnie” (`event_interests`) | lista uczestników |
| Kierownik | Panel kierownika w Sprzęcie (sprzęt bez limitu) | widok uczestników |
| Google | Sheets, Calendar, Gmail, Groups (DWD admin@) | **zakres Drive** |

## Decyzje (02.11.2026)
| # | Decyzja |
|---|---|
| D1 | Źródło prawdy = **aplikacja**; arkusz per impreza = lustro tylko do podglądu |
| D2 | Uczestnicy: konta aplikacji (zapis sam) + **goście** dopisywani przez kierownika (imię, nazwisko, e-mail) |
| D3 | Wpłaty **zawsze na konto klubowe** (SETUP `konto`) |
| D4 | Potwierdza **kierownik tej imprezy LUB skarbnik** (kto pierwszy); zapisujemy kto i kiedy |
| D5 | Cena = **warianty** (np. „z noclegiem”, „gość”), każdy: kwota, opcjonalnie zaliczka |
| D6 | Rezygnacja po wpłacie: **kierownik decyduje o zwrocie** (kwota); skarbnik ma listę zwrotów → „zwrot wykonany” |
| D7 | Tylko imprezy **organizer = morzkulc** z kierownikiem |
| D8 | Od startu: limit miejsc + lista rezerwowa, termin wpłaty + przypomnienia, zaliczka + dopłata, zamknięcie zapisów |
| D9 | Ustawienia zapisów w **Panelu kierownika** po zatwierdzeniu imprezy; arkusz imprez bez nowych kolumn; ceny edytowalne do pierwszej wpłaty |
| D10 | Rezerwowy **awansuje automatycznie** + mail z danymi do przelewu; termin wpłaty liczony od awansu |
| D11 | Brak wpłaty w terminie: **mail + czerwone oznaczenie**, usuwa kierownik ręcznie |
| D12 | Arkusz-lustro: katalog „Imprezy — rozliczenia/ROK”, udostępniony **do odczytu kierownikom + skarbnikowi** |

## Model danych
**`events/{id}.signup`** (nowe pole, tylko impreza klubowa)
| Pole | Opis |
|---|---|
| `enabled` | zapisy włączone |
| `variants[]` | `{id, label, pricePln, depositPln|null}` |
| `capacity` | limit miejsc (null = bez limitu) |
| `closesAt` | koniec zapisów (YYYY-MM-DD) |
| `depositDueAt`, `balanceDueAt` | terminy zaliczki / całości (bez zaliczki → tylko `balanceDueAt`) |
| `pricesLocked` | true po pierwszej potwierdzonej wpłacie |
| `sheet` | `{fileId, url, syncedAt}` lustra |

**`event_signups/{id}`**
| Pole | Opis |
|---|---|
| `eventId`, `uid` / `guest{firstName,lastName,email}`, `addedBy` | osoba (gość bez konta) |
| `variantId`, `amountPln`, `depositPln` | wariant zamrożony przy zapisie |
| `list` | `main` / `waitlist` / `cancelled`; `position` (kolejność rezerwy), `promotedAt` |
| `payments.deposit`, `payments.balance` | `{status: none|reported|confirmed, confirmedBy, confirmedAt}` |
| `refund` | `{amountPln, decidedBy, doneAt, doneBy}` |
| `code` | KOD6 do tytułu |

Tytuł przelewu: `Impreza <nazwa, skrócona> Imię Nazwisko (ID: n); KOD6`, gość: `(gość)` zamiast ID. Limit długości tytułu bankowego (140 zn.) → skracamy nazwę imprezy.

## Przepływy
| Kto | Co |
|---|---|
| Uczestnik | Imprezy → „Zapisuję się” (wybór wariantu) → lista główna albo rezerwowa → mail z danymi przelewu; „Zapłaciłem” (opc.); „Rezygnuję” (przed wpłatą bez skutków; po wpłacie → kierownik decyduje o zwrocie) |
| Kierownik | Panel kierownika → impreza → **Ustawienia zapisów** / **Uczestnicy**: statusy (zapisany, zgłosił wpłatę, zaliczka ✓, opłacone ✓, po terminie 🔴, rezerwa, rezygnacja), Potwierdź zaliczkę / całość, dopisz gościa, usuń, decyzja o zwrocie, przypomnij (1 / zaznaczeni), podsumowanie (miejsca, wpłacone zł, do zapłaty zł) |
| Skarbnik | to samo potwierdzanie dla wszystkich imprez + lista zwrotów do wykonania (Panel Zarządu → Składki/Imprezy) |
| Zarząd/KR | podgląd wszystkich imprez płatnych |
| Automat | awans rezerwowego + mail; przypomnienie N dni przed terminem i po terminie (raz); arkusz-lustro odświeżany po każdej zmianie |

Automat dzienny dopięty do istniejącego schedulera (bez nowej funkcji — darmowa strefa, invoker).

2. Utworzyć na Dysku admin@ katalog „Imprezy — rozliczenia”, wpisać jego ID do SETUP.

## Otwarte (drobne — zdecyduję domyślnie, chyba że wskażesz inaczej)
- Impreza odwołana / odrzucona po wpłatach → wszyscy wpłacający trafiają na listę zwrotów (pełna kwota).
- Zmiana kierownika → udostępnienie arkusza przechodzi na nowego, stary traci dostęp.
- Arkusz-lustro bez telefonów i e-maili (RODO) — imię, nazwisko, wariant, statusy, kwoty.
